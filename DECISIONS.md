# Decisions (where the brief was silent)

- **Project location:** `carousel-studio/` subfolder (the parent dir already holds unrelated `.venv`/`.idea`).
- **TypeScript 6, not 7:** Next 15 needs the JS compiler API that TS 7 dropped.
- **Hash:** scrypt (Node built-in, N=16384) instead of argon2id, to avoid a native dependency.
- **Middleware runs on the Node runtime** (`runtime: "nodejs"`, stable in Next 15.5) so it can read the session epoch from `data/`.
- **Session cookie:** `epoch.expiry.HMAC`. Rotation bumps `epoch`, which kills every older cookie. The rotating browser gets a fresh cookie.
- **Rate limiter:** in-memory, per IP, 5 fails / 15 min, lockout doubles on repeats (cap 24h). `X-Forwarded-For` is only trusted when `TRUST_PROXY=1`; otherwise every client shares one bucket (safe default for a single-token gate, but one attacker can lock out everyone, which is the cost of not trusting spoofable headers). Resets on server restart.
- **`APP_ACCESS_TOKEN` set in env:** that value is the token; Rotate is refused (409) because the env would win again at restart.

## Phase 1
- **Default models** (verified against OpenRouter `/models` on 2026-11-25; stable IDs, not previews): `vision_strong` google/gemini-2.5-pro ($1.25/$10 per M), `text_cheap` google/gemini-2.5-flash ($0.30/$2.50), `vision_cheap` google/gemini-2.5-flash-lite ($0.10/$0.40). Newer 3.x models exist but are previews/unknown on Gemini-direct. All overridable in Settings.
- **USD→INR 92.93** (open.er-api.com, 2026-11-25), editable with date stamp in Settings.
- **Timeout:** 45s default per brief; the ingest vision call passes 180s (a Pro-class call over ~8 images routinely exceeds 45s, and a timeout would double-spend via fallback).
- **Gemini thinking tokens** are billed as output and counted in `out_tokens`.
- **Failed attempts are logged** (`ok=0`) with their tokens, since they cost money.
- **Gemini key** goes in the `x-goog-api-key` header, never the URL.
- **Error redaction:** every stored key is scrubbed from any error text.
- **Look book PDFs are test input only:** `fixtures/` holds a sample; no code or prompt mentions its content. Page size comes from the PDF; the output canvas is fixed 1080×1350 per brief.
- **Palette:** k-means runs on 24-dpi PPM renders (no image library), pooled across ≤12 pages.
- **Devanagari pairs are verified, not trusted:** a pair must ship a `devanagari` subset on Google Fonts, else it's replaced by Noto Sans Devanagari with a visible warning. Found because two of three look books got Latin-only mono families from the model.
- **Spec lint** (`lib/ingest/lint.ts`) cross-checks machine rules against colours/archetypes (e.g. "alternate to yellow" with no yellow archetype) and surfaces warnings instead of letting the generator trip later.
- **Palette** snaps to the mode colour per cluster (see commit notes): exact brand hexes even when the PDF has no hex text.
- **Phase 3 note:** `forbid` patterns may use `\p{..}`; compile them with the `u` flag.

## Phase 2
- **Kit stays a separate call from the spec call** (brief: measure both, pick cheaper). Output tokens dominate cost (~10k–14k each); merging saves only ~4k input tokens (~0.5¢) and would make repairs all-or-nothing.
- **Deterministic vs LLM split in the kit:** `@font-face`, `:root` colour/font/margin variables are generated by code from the spec; the LLM writes only element/layout CSS and archetype HTML and may only reference `var(--c-*)`/`var(--font-*)`. Hex outside `:root` is rejected.
- **Root is enforced by the renderer** (fixed 1080×1350 container) and verified by measurement, rather than trusting the LLM's root element.
- **Fit engine** runs in-page: binary search on font-size between `data-min-size` and `data-max-size`; tolerance of 0.12em vertically because a font's content area can exceed a tight line-height with no visible clipping (found when a headline was needlessly shrunk 220px→100px).
- **Fonts fail loudly:** `document.fonts.check()` returns true for unknown families, so we call `document.fonts.load()` for each Latin family (with "Ag") and each Devanagari pair (with क्ष त्र श्र) and fail the render if it returns no face.
- **Kits can't reach the network:** Playwright aborts all http(s) requests during render.
- **Fidelity judge:** flash-lite scored a left-vs-centre alignment mismatch 95, so `vision_cheap` now defaults to gemini-2.5-flash, render+reference are sent as ONE side-by-side image, and the final score is computed in code (60% mean + 40% worst category) from per-category scores. Repair triggers when ANY archetype scores <75 (brief says <75 → repair; we apply it per archetype).
- **Repair budget:** at most 1 constraints repair + 1 fidelity repair per kit; a fidelity repair that lowers the score is rolled back.
- **Known limit:** the judge is still noisy (occasional invented diffs). Treat the score as a repair signal, not ground truth; the PNGs are the real evidence.

## Phase 2b (quality)
- **Slide geometry is measured, not guessed:** `pdftotext -bbox-layout` (word boxes), `pdftohtml -xml` (exact font family/size/colour per run), `pdftocairo -svg` (vector fills → slide frames). Slides are located per page as ~4:5 background fills (tolerance 0.70–0.84 w/h, because strips have caption margins); several frames per page are supported and assigned to archetypes by background colour then role (cover first, closer last).
- **Fidelity is measured on the PDF itself:** word-position match + size ratio + SSIM/colour diff against the exact reference crop, per archetype. The LLM judge is informational and is the only signal where the post can't be located.
- **Best-of-3 kit generation** (concurrent), chosen by measured score, then a free deterministic aligner (shape → position cycles, per-archetype acceptance), then at most the single constraints repair. The extra *measured LLM repair rounds were switched off by default* (`KIT_REPAIR_ROUNDS=0`): across runs they were discarded far more often than kept and cost ~$0.2 each.
- **Known gap:** decoration that isn't text (a margin line's x position, glows, textures) can't be fixed by the aligner. Example: Small Print's inner paper slide keeps the red margin line at the cover's x while its reference moves the text left of it.

## Phase 3 (generation)
- **One copy call for both platforms** (`text_cheap`), static content first (instructions + spec digest + slot budgets in the system message), topic/N/language last. Overrides only for slots that differ.
- **Archetype sequence is decided in code when the rules and kit determine it** (`planSequence`): first/last position rules and background rotation over the cover's id-prefix family. The model is told exactly which archetype each slide uses; otherwise it chooses and the validator checks.
- **Validation is code**: per-slot words/chars, required/unknown slots, max-words-per-slide, element limits, `forbid` regexes (`u` flag; "emoji" maps to `\p{Extended_Pictographic}`), first/last archetype, background rotation, script per language (Hindi ≥60% Devanagari, with a short list of Latin acronyms like SIP/EMI allowed; English/Hinglish: zero Devanagari), caption/hashtag limits per platform.
- **Repair = one batched call for failing slides only**, never a second round. Remaining problems are saved as per-slide flags and fixed inline for ₹0.
- **What counts as a flag:** validation failures and overflow *caused by the copy*. Template defects that already existed when the kit was built (listed in the kit's report), furniture-position issues, and overflow where the text is already inside the slot's budget are not blamed on the user's copy.
- **Empty or omitted optional slots disappear together with a wrapper that exists only for them** (an empty stamp box otherwise renders).
- **PDF = lossless PNG per page at 1080×1350** (`pdf-lib`), not `page.pdf`: it is pixel-identical to the PNG by construction; text isn't selectable. Instagram/LinkedIn PNGs are rendered once when no slot or handle differs.
- **Inline edits and regeneration:** edits re-render in code (no LLM, ₹0). Regeneration is one cheap call carrying the digest, that slide's slot schema, neighbours' headlines and the instruction; only that slide's files change (verified by `scripts/regen-test.ts`).
- **Cost estimate before generating** = tokens (chars/3.6 + overhead) × live price of the text model, deliberately a slight over-estimate (thinking tokens included).

## Phase 3b (quality at ₹10 / carousel)
- **Budget raised to ₹10 per carousel**, spent where it is visible: the per-carousel text call moved to a new `text_strong` tier (default `google/gemini-2.5-pro`) with a capped thinking budget; repair and single-slide regeneration use it too. Measured: ₹7.2–8.2 per carousel (copy ₹4.2, cover director ₹1.8, repair ₹1.2–2.2, judge ₹0.08).
- **Cover director** (`lib/generate/cover.ts`): after the copy is validated it writes 4 alternative covers with different hook angles (question, number/claim, myth-bust, curiosity gap). All are rendered (free), invalid ones are dropped by the same deterministic checks (limits, rules, script, overflow, invisible text), and a vision judge (`vision_cheap`, one call on a labelled contact sheet) scores hook / visual / brand; the winner is chosen by a weighted total computed in code. If the director or judge is unavailable the original cover is kept.
- **Typography polish at generation time only** (`polish: true`): balanced headline/number/CTA line breaks, `text-wrap: pretty` for running text, no auto-hyphenation. Off at ingest so kits are still measured against the reference as printed.
- **Kit quality (ingest):** exact logo crop from a 4× render (found as the compact non-text blob in its furniture corner, flood-filled alpha) and substituted deterministically into the logo furniture of every archetype; margin lines/dividers detected in render vs reference (colour-based, so text touching the line can't hide it) and fixed with an archetype-scoped CSS override incl. opacity; furniture absent from an archetype's own reference (e.g. a handle on a cover) is hidden for that archetype unconditionally.
- **Judge is never load-bearing for ingest:** if the vision judge fails the ingest still completes with the measured score.

## Phase 4 (UI)
- Screens: Brands (grid, create + PDF upload + streamed ingest, delete with confirm), Brand (versions, set active, delete, upload new, full style review), Create (estimate before generating, SSE stages), Carousel (IG/LinkedIn, strip, inline edit with live limits, regenerate with instruction + template picker, flags, cost panel, downloads, captions), Settings (masked keys + test, models per tier + live list, pricing, FX, rotate token).
- **Saving the style review never calls an LLM.** Colours, fonts (re-downloaded), budgets and previews are recompiled deterministically from the stored kit. Structural changes (archetypes, slots, elements on/off) mark "rebuild needed"; rebuild shows its estimated cost first.
- **Inline edit is a field panel next to the preview** (with per-slot word/char counters), not click-on-pixels: slot geometry isn't stored per render, and a field panel is more reliable on touch.
- `next build` was broken by TypeScript 6's side-effect-import check on `.css` (found only when building for production); fixed with `types/css.d.ts`.

## Phase 4b (look book comprehension, guideline register, checklist, UI rebuild)
- **Every look book follows one document anatomy** (told by the product owner): profile · brand system (colours, elements, type, pillars) · one page per single-post format · carousel cover · "inside the carousel" (slide plan bullets + voice) · logo. So the structure is **parsed deterministically** (`lib/ingest/anatomy.ts`) from text blocks/lines with coordinates, keyed on the shared section headings, never on brand words. It is exact, free and testable offline; the vision model is used only for what needs understanding (the design itself) and is *handed the parsed facts as ground truth*.
- **Parser robustness found with the two re-built fixtures** (same anatomy, different style): letter-spaced headings extract one "word" per letter (rebuilt from gap analysis, glyph-size aware); kerning-width splits ("BOT TOM") are merged; pdftotext glues same-baseline text from different columns (lines are split on wide gaps and on baseline/size jumps); wrapped captions are grouped per column by contiguity and punctuation; artwork-only columns are dropped. Result: 100% block coverage and no warnings on all three look books.
- **Guideline register** (`lib/ingest/guidelines.ts`): every statement becomes an atomic guideline with page, **verbatim quote**, category, scope and a declared verification method: `code` (checked on the output), `template` (verified in the kit), `review` (AI, after generation), `info`. Classification is by the look book's own wording (slide roles, "alternate X and Y", "A only on B", "max N words", "one X per slide", "no photos", "sources in the caption", furniture positions, "always show the maths", colour usage, font roles, elements, feed rules, pillars). 40/40/39 guidelines on the three look books. Grounding test: every word of every quote must appear on the guideline's own PDF page.
- **Written rules beat sample artwork.** The real look book contradicts itself (its inside-slide sample puts the counter top-left; its rule says top-right). The aligner no longer drags furniture toward a sample, and `enforceFurniture` moves furniture to the side its rule states, inside the margins.
- **Checklist** (`lib/generate/checklist.ts`): all guidelines evaluated against what was produced: copy, computed fonts/colours of every rendered slot, rendered backgrounds, pixels (palette), PNG sizes, the template kit's HTML/CSS, captions. Items carry **evidence**, who checked them (code / template / AI), the look book page, and the slides involved. Code and template checks are free and recomputed live (so an inline edit flips an item immediately); the AI review runs once at the end of generation (flash, ~₹0.3) and is marked stale after edits.
- **The generator is given the register**: formats (it picks the best carousel format; the user may choose), slide plan, every binding guideline with its page. Slide-role rules (cover = hook question + stamp; last slide = fix + "Save this" stamp), "show the maths" and caption sources are enforced by the validator, so the single repair call fixes violations. Sources are appended to the captions themselves, because the look book asks for sources in the caption.
- **Existing look books get the register for free** (`ensureGuidelines`/`upgradeLookbook`, deterministic) and existing carousels can be re-rendered with the current templates for free (`rerenderCarousel`).
- **UI rebuild**: design tokens, icons, toasts, skeletons, empty states; brands as cards with palette + guideline count; brand page with Guidelines / Style / Carousels / Versions tabs; create flow with format choice and a "what will be applied" summary; carousel page with slide rail (failing slides marked), keyboard navigation, and a side panel whose default tab is the **Checklist**; ordered progress steps instead of a spinner.
- **Known gaps**: Gemini fallback still untested live; decorations that are raster textures can't be tuned by the aligner; the look book's own inside-slide archetypes are the weakest templates (fidelity ~60-70).

## Phase 5 + quality round
- **Kit generation is adaptive**: one candidate first; two more only if its measured score is below 75 (`KIT_BAR`). Measured on two look books: one candidate scored 83 and 87, so ingest is about a third cheaper.
- **Readability is enforced in code at three points**: static `fixContrast` when a kit is written, `enforceReadable` from rendered colours at ingest, and a built-in "text is readable" checklist item at generation. Found because a model copied white text onto a light cover.
- **The slide plan is applied by code** (`applyPlan`): cover, alternation and closer templates are set after the model writes, when the templates take the same slots. Previously alternation failed whenever the model ignored the prompt.
- **Self-correction**: after the review, guidelines reported broken on specific slides get one repair call; a fix is kept only if it validates and renders cleanly. Repair runs up to two rounds when hard violations remain.
- **Fixture bug found**: the synthetic look books had duplicate `style` attributes (colours dropped) and the second look book used its gold accent as a slide background. Fixed the fixtures, not the product.
- **Tests added**: no-hard-coding grep (it caught a real brand name in a UI placeholder), auth, Devanagari shaping, upload failure handling, zod contracts.

## Model trial for template generation
- Added a `kit_strong` tier (Settings) so the template-building model can be changed on its own. Tried Claude Opus 5.5 ($4/$20 per M tokens) on the real look book: about $1.3 per ingest (3 candidates + repair), 2.7 min per candidate, and measured fidelity 50 against about 75 for Gemini 2.5 Pro. The Opus kit came back with placeholder sample text (HEADLINE, BODY) instead of the look book's sample wording, which breaks the measured alignment loop. Not better, so the default stays Gemini 2.5 Pro. Anthropic models need a stricter JSON schema; `anthropicSafe` in `lib/llm/openrouter.ts` converts it.
- Found and fixed a bug in the stamp normaliser that broke self-contained stamps (the slot is the box) by removing their positioning.
- Pixel-level polish added: text colour is judged against what is painted behind it (not the slide background), slots always paint above decorative boxes, a furniture element that duplicates a slot is hidden, counters never wrap. The "revert polish" safety net now triggers only on new render problems, never on lower similarity to the sample.

## Single posts (quiz) in Create
- The look book's one-slide formats (The Number, Quick Maths) can be generated from Create ("Single post"). The template is fixed by the look book page the format comes from (`singleOf`), not chosen by the model.
- One slide, no cover/closer/alternation/counter: carousel-only guidelines (`carouselOnly`: slide roles, rotation, first/last, "show the maths", slide counter) are skipped in validation, excluded from the AI review and shown as n/a in the checklist.
- Quiz logic (curiosity, not the answer): when the template has 3+ answer options the model is told to write a specific question, one correct and plausible others, never reveal the answer on the slide or in the caption, and to keep the whole slide within the word limit. A built-in AI-review item "does not reveal the correct answer" is added, and answer options are never trimmed by the word-cap code (a clipped option is a wrong answer).

## Live-test fixes (progress stream, quiz options, edge, type consistency)
- **Progress stream**: a comment line every 10s keeps proxies from dropping a silent connection during kit building; if the connection still drops, the brand page waits on the look book's status instead of showing a stuck screen. The job itself never depended on the connection.
- **Quiz options come from the look book's lettered boxes** (`expandOptionSlots`): the spec gets one slot per A/B/C/D box before the template is built, so the model can no longer return one "options" slot that the template repeats in every box.
- **Receipt edge is always ours**: the model's own drawing of the edge element is removed and replaced by the code-drawn band (own class, so the model's CSS cannot turn it into a dotted line).
- **Type and spacing consistency**: inside slides share one size per role (lower median; only slides that need smaller text for long copy keep it), edited and regenerated slides inherit it, stacked slots keep breathing room (a quarter of the upper line, at least 14px), running text never shrinks below 65% of its designed size and 26px (longer copy is rewritten shorter instead), and centred text in unsampled templates is left-aligned.

## Template hygiene (always on, unless the look book says otherwise)
- Applied to every kit at ingestion, after the measured alignment: text inside the margins and clear of rule lines; a cover headline at least as big as the inside headlines (the hero type); display type never shrinks below 60% of its designed size and running text never below 65% / 26px (longer copy is rewritten shorter); tag and slide counter share one line, handle and logo share one line; in templates with no sample, one text alignment (left) and a text column that spans the margins, equal padding left and right.
- `hygieneExempt` reads the look book's own statements (guidelines, rules, elements, voice) about alignment, pixel sizes and padding/margins; a stated rule switches the matching default off. Sampled templates keep the alignment measured from the sample.

## Skeleton-first ingestion (templates built from the PDF's measured layout)
- `lib/ingest/skeleton.ts` builds each archetype that has a measured sample (geometry from the PDF vector data) straight into HTML: boxes, font sizes, line pitch, alignment, ink (palette colour at an opacity), shapes, the real logo position. The spec says what each template contains (slots, furniture); the geometry says where and how it is drawn. Slots are paired with blocks by kind and reading order. Tracked (letter-spaced) text and tilted stamps are rebuilt from the PDF's glyph runs.
- `compileKit` tries it first, for free. If every template is covered, no layout model call is made; if some have no sample, the model builds only those; if the measured score is below the bar, the usual model candidates are generated and the best measured kit wins. `KIT_SKELETON=0` switches it off.
- Decoration the PDF draws as effects (ruled paper, torn edges, stamp frames) cannot be measured. One focused model call (`kit_decor.md`) adds it as empty elements behind the content; the text layer must come back byte-identical and the measured score must improve, otherwise it is discarded. It only runs when the spec lists decorative elements. `KIT_DECOR=0` switches it off.
- Templates built this way, and templates edited by instruction, are exempt from the positional polish (balance, clearance, row/column alignment): the look book's own layout wins.
- Measured with the real compile on the three sample look books (hand-written specs, stubbed model): final fidelity 94 / 91 / 90, zero layout model calls, zero render problems, also with 1.6x and 0.5x copy length.
- Known limits: bold on variable fonts is not visible in the PDF's font names; the slide counter cannot be zero-padded ("02 / 05"); a spec slot with no counterpart in the sample is placed under the content; decoration needs the model.
